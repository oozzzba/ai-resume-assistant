# JD 简历匹配助手｜0-1 产品设计包（MVP 正式版）

**版本**：MVP v1.0｜**状态**：待内测｜**产品负责人**：待确认｜**文档日期**：2026-10-21  
**单一事实源**：本文件。需求、风险、测试与迭代均以需求编号追溯。

## 1. 立项与边界

### 1.1 问题与价值假设

27/28 届学生常用同一份简历海投，无法将真实经历与 JD 对齐；通用生成工具又可能把“优化”越界为虚构。假设：提供“原文核对 + JD 对照 + 可追溯建议 + 幻觉阻断”，可让用户更快完成可信的岗位定制，而不增加简历诚信风险。

**目标**：帮助用户识别匹配短板、润色已存在内容、获得可执行的真实信息补充清单。  
**不做**：替用户编造内容、评价候选人是否一定适合岗位、自动投递、排版设计、历史简历库、RAG。RAG 不解决本产品的主风险（模型擅自补写），一期不引入复杂度。

### 1.2 用户与任务

| 用户 | 核心任务 | 当前阻碍 | 产品结果 |
|---|---|---|---|
| 无/少实习应届生 | 为一个 JD 修改一版简历 | 不知缺什么，担心 AI 胡编 | 明确“可改”与“需补充真实信息” |
| 有项目经历应届生 | 将原有经历表述对齐职责 | 关键词、结构不匹配 | 可追溯的润色文本与逐条建议 |
| 内测运营/产品 | 判断输出是否可靠 | 难以发现隐性编造 | 风险拦截结果与反馈数据 |

### 1.3 北极星与验收信号

北极星指标：**完成 JD 匹配分析后，被用户下载或复制优化简历的比例**。MVP 内测只采集基线，不预设虚构数值。辅助指标：解析成功率、分析成功率、40 秒内完成率、结果下载率、反馈数、内容不符合 JD 的负反馈率。指标阈值、模型成本和并发上限均待内测后由产品/算法确认。

## 2. 用户故事与主流程

| ID | 用户故事 | 优先级 | 成功定义 |
|---|---|---:|---|
| US-01 | 作为应届生，我要上传 PDF/DOCX 并核对解析文本 | P0 | 文件合规时显示文字；扫描件/损坏件被友好拦截 |
| US-02 | 作为应届生，我要粘贴 JD，或无 JD 做通用润色 | P0 | JD 清洗截断可见；留空不阻塞 |
| US-03 | 作为应届生，我要看到匹配分、依据、润色稿和建议 | P0 | 输出按固定结构展示并可下载 |
| US-04 | 作为应届生，我要知道每项建议依据何处 | P0 | 每项建议含原文依据；关键表述含追溯链 |
| US-05 | 作为内测参与者，我要提交不含简历内容的反馈 | P0 | 匿名反馈可入库，不关联简历/JD |

```text
上传/粘贴 → 格式、大小、内容校验 → 原文预览与人工确认 → JD 清洗
→ 受约束模型调用 → Schema/数字/追溯链检查 → 通过则展示和下载；不通过则拦截并提示重试
→ 匿名反馈 → 周度归因 → Prompt/规则/交互迭代 → 回归测试/灰度
```

## 3. PRD

### 3.1 范围与页面

| 页面/模块 | 需求 ID | 输入与约束 | 系统行为 | 输出/状态 |
|---|---|---|---|---|
| 上传与解析 | FR-01 | PDF/DOCX，单件 <=10MB | 提取文字；文字少于 40 字视为扫描件/不可用 | 原文预览；格式、损坏、扫描件错误态 |
| 简历粘贴 | FR-02 | 最长 18,000 字 | 清除零宽字符、压缩空白、截断提示 | 可核对原文 |
| JD 输入 | FR-03 | 可空，最长 12,000 字 | 清洗乱码/多余空白，安全截断 | 正常或“已精简”提示 |
| 人工确认 | FR-04 | 必选勾选 | 未确认不可分析 | 禁用/可用按钮态 |
| 智能分析 | FR-05 | 已确认的简历 + 可选 JD | 调用 DeepSeek，超时 40 秒 | 加载、成功、失败、重试态 |
| 结果展示 | FR-06 | 结构化结果 | 显示分数、依据、润色稿、建议、信息不足项、追溯链 | 下载 TXT；不提供自动投递 |
| 安全拦截 | FR-07 | 模型输出 | 数字、Schema、原文追溯链检查 | 高风险时不展示生成稿，仅保留原文 |
| 内测反馈 | FR-08 | 昵称、1-5 分、文字反馈 | 不接受简历/JD；仅本地 JSONL | 成功提示 |

### 3.2 AI 规格

**能力边界**：模型仅进行匹配判断、语言润色、结构重组、基于 JD 的建议；不能写入外部系统，不能以知识补齐用户经历。会话无记忆；简历/JD 仅在当前请求中使用，应用不持久化它们。

**模型**：DeepSeek API，`deepseek-chat`，OpenAI 兼容端点。温度固定 `0`，最大输出 `3800 tokens`，客户端超时 40 秒；模型版本、成本、并发、降级模型由算法/工程负责人待确认后写入发布单。

**Prompt 版本 P-1.0**：系统提示词已固化于 `app.py`，包含最高优先级禁止编造、不可变更数字/专名、JD 注入隔离、严格 JSON、证据字段和信息不足反馈。输入作为 JSON 数据传递，不与系统规则拼接；不得通过用户文本覆盖规则。

**输出 Schema**：`match_score`（0-100 整数）、`match_summary`、`matched_requirements[]`、`gaps[]`、`optimized_resume`、`suggestions[{title,detail,evidence}]`。任何 Schema 失败均视为生成失败。

### 3.3 验收标准（Given / When / Then）

| 需求 | 验收标准 |
|---|---|
| FR-01 | Given 上传扫描 PDF，When 解析，Then 不调用模型并提示上传文字版。 |
| FR-03 | Given JD 超长，When 提交，Then 清洗截断并向用户提示；仍可分析。 |
| FR-04 | Given 未勾选原文确认，When 点击分析，Then 按钮不可用。 |
| FR-05 | Given API 在 40 秒内返回合法 JSON，When 分析，Then 进入输出检查；超时/乱码给重试提示。 |
| FR-06 | Given 输出通过校验，When 打开结果，Then 用户能看到固定五类内容并下载文本。 |
| FR-07 | Given 输出含原文不存在的数字或错误追溯片段，When 校验，Then 生成简历不展示且写明拦截原因。 |
| FR-08 | Given 用户提交反馈，When 入库，Then 记录中不含简历/JD 字段。 |

## 4. 多层幻觉防御与风险闭环

### 4.1 防线设计

| 层级 | 机制 | 拦截对象 | 失败处置 |
|---|---|---|---|
| L0 产品边界 | 原文预览、人工确认、明确“不可虚构” | 输入错位、用户误信 | 禁止分析，要求核对 |
| L1 系统提示词 | 最高优先级规则、JSON Schema、证据输出 | 模型自由发挥、提示注入 | 模型拒绝/信息不足而非补写 |
| L2 输入网关 | 格式/体积/字符/扫描件/JD 截断 | 恶意、不可解析、Token 超限 | 拦截或截断并告知 |
| L3 输出网关 | JSON、分数范围、数字差异、原文追溯片段 | 新数据、无依据陈述、乱码 | 阻断结果，显示原文与重试路径 |
| L4 人工闸门 | 用户最终核对，内测者标记不实 | 语义级漏检 | 反馈归因、下线 Prompt/模型版本 |
| L5 运营治理 | 版本、抽检、金标集、灰度、回滚 | 回归与模型漂移 | 关闭模型入口或回退已批准版本 |

### 4.2 Bad Case 风险清单

| 风险 ID | 场景/触发 | 等级 | 当前控制 | 责任人 | 闭环证据 |
|---|---|---:|---|---|---|
| R-01 | 模型增加不存在的项目、公司、技能 | 高 | L1+L3+L4 | 算法/产品 | 追溯失败率、抽检记录 |
| R-02 | 模型篡改原有数字、时间、排名 | 高 | 数字集合对比，阻断 | 工程 | 被拦截样本与回归用例 |
| R-03 | JD 含“忽略规则/编造经历”等注入 | 高 | 不可信数据隔离、固定系统规则 | 算法/安全 | 注入测试集通过率 |
| R-04 | 语义改写引入原文未支持的结论但无数字 | 高 | 追溯链、人工核对、内测标注 | 产品/算法 | 人工抽检与金标集 |
| R-05 | 扫描件误解析或文件损坏 | 中 | 文字阈值与异常捕获 | 工程 | 解析失败原因分布 |
| R-06 | 简历/JD 泄露或被长期存储 | 高 | 不落盘、反馈去内容化、密钥环境变量 | 工程/安全 | 代码审计、访问日志 |
| R-07 | 输出截断/非 JSON/API 失败 | 中 | Schema 验证、超时、重试提示 | 工程 | 错误率、调用日志 |
| R-08 | 用户将建议当成真实能力认证 | 中 | 页面声明、信息不足项、人工确认 | 产品 | 反馈与可用性测试 |

### 4.3 管控闭环

发现（输出拦截、用户反馈、抽检）→ 记录（风险 ID、Prompt/模型/规则版本、脱敏样本、严重度）→ 分流（P0 立即关闭生成；P1 24h 内回退/修复；P2 纳入周迭代）→ 修复（Prompt/规则/UI）→ 金标回归 → 小流量内测 → 发布审批。任何高风险漏出必须完成根因分析并更新对应 R 编号、测试用例和版本记录。

## 5. 数据、隐私与可观测性

**数据最小化**：简历/JD 只在请求内存中处理，不写文件、数据库、分析事件或反馈记录。反馈只保留时间、匿名编号、评分和文本，界面要求不得填写敏感内容。生产环境应由安全负责人进一步确认 API 服务商的数据处理条款、密钥轮换、TLS、日志脱敏和数据删除流程。

**建议埋点（不含正文）**：`upload_started`、`parse_succeeded/failed{reason}`、`jd_truncated`、`analysis_started`、`model_failed{type}`、`output_blocked{risk_id}`、`result_downloaded`、`feedback_submitted{score}`。事件必须不含文件名、简历、JD、API Key、模型原文。

### 6.2 五人内测执行方案（不虚构结果）

招募 5 名符合目标画像的学生，覆盖无实习（2 人）、有项目（2 人）、有实习（1 人）；每人使用一份脱敏且真实的简历和一个目标 JD。依次完成：上传/核对（2 分钟）→ 分析（2 分钟）→ 标记每一条不实或不清晰内容（3 分钟）→ 评分与访谈（5 分钟）。测试主持人不获取简历原文，仅记录任务是否完成、风险是否被拦截、耗时、评分和匿名原话。
