## 1. 产品概述

### 1.1 背景

各类求职者常用一份简历投递不同岗位，简历中的项目、技能与目标岗位 JD 未建立清晰对应，导致 ATS 关键词命中不足、HR 无法在首页快速识别匹配证据。用户需要的不是简历真伪判断，而是基于已提供的简历内容，理解自己与一个目标岗位的匹配程度，并得到可直接使用的定制简历。

### 1.2 定位与价值

面向所有求职者的 JD 驱动简历匹配与优化助手。输入真实简历和目标岗位 JD 后，系统完成关键词提取、可解释匹配评分、差距识别、结构调整、针对性修改建议和完整优化简历输出。

价值假设：把 JD 的高优先级要求与简历中已有证据一一关联，可降低用户自行改简历的难度，并提升投递材料的岗位相关性。

### 1.3 目标与非目标

**MVP 目标**

- 在一次会话中完成“简历 + JD → 匹配分 → 优化简历 → 投递前自查”的闭环。
- 让匹配分和扣分依据可解释，用户知道该补什么、如何改。
- 在不新增用户经历、技能或数据的前提下，输出一份可复制、可下载的完整简历。

**非目标**

- 不核验简历真实性，不作录用预测、薪资预测或自动投递。
- 不长期保存简历/JD，不做用户简历库与多版本历史记录。
- 不在一期提供在线面试模拟、PDF 排版导出或简历模板编辑器。

## 3. 业务流程与状态

### 3.1 用户可见 SOP

```text
步骤 1 上传/粘贴简历
  → 格式与文本解析校验 → 原始简历预览
步骤 2 粘贴目标岗位 JD
  → 清洗、截断 → 提取岗位关键词与职责
步骤 3 进行 JD 匹配
  → 100 分制评分 → 展示得分、扣分原因、匹配项与缺口
步骤 4 优化与投递
  → 输出优化结构、完整优化简历、修改建议、投递前自查
二期：基于已确认的 JD 与优化简历生成面试准备材料和模拟问答
```

### 3.2 状态机

| 状态 | 进入条件 | 用户操作 | 退出条件 |
|---|---|---|---|
| `draft` | 初始进入页面 | 上传/粘贴简历、JD | 有效简历文本 |
| `resume_ready` | 简历解析成功 | 核对原文、输入 JD | 用户确认素材 |
| `analyzing` | 点击“开始 JD 匹配分析” | 等待或重试 | 模型返回/超时/错误 |
| `result_ready` | 输出通过 Schema 校验 | 查看、复制、下载、反馈 | 发起新分析 |
| `error` | 文件、输入、模型或输出异常 | 修正输入、重试 | 回到 `draft` 或 `resume_ready` |

## 4. 信息架构与页面交互

### 4.1 页面布局

顶部固定显示四步进度：`上传简历 → 提供 JD → 匹配评分 → 优化与投递`。页面主体按当前步骤显示内容，不把二期面试能力混入 MVP 主流程。

| 区域 | 内容 | 交互要求 |
|---|---|---|
| 进度条 | 4 个步骤与当前状态 | 未满足前置条件的步骤不可直接跳转 |
| 简历输入 | 上传 PDF/DOCX、文本粘贴、原文预览 | 支持 10MB 文件；扫描件提示更换文字版 |
| JD 输入 | 文本输入与已清洗提示 | JD 可空；留空时进入通用优化 |
| 分析结果 | 得分、原因、匹配项、缺口 | 固定结果结构，支持定位到对应 JD/简历证据 |
| 优化结果 | 推荐结构、优化简历、修改说明 | 文本复制与 TXT 下载 |
| 投递前自查 | 覆盖度、首页证据、成果、关键词、可选风险说明 | 每项展示状态和下一步动作 |

### 4.2 结果页结构

1. **JD 匹配度**：0-100 分、等级标签和一句话结论。
2. **得分与扣分依据**：按评分维度列出已获得分数、未获得分数及原因。
3. **已匹配的 JD 要求**：一项 JD 能力对应至少一个简历证据。
4. **待补充或强化方向**：仅提示用户补充真实经历、数据或材料，不补写内容。
5. **建议的岗位定位**：原文证据充分时给出三句式定位；不足则留空并提示。
6. **优化结构说明**：岗位定位、关键技能、核心经历/项目、教育经历的推荐顺序及调整原因。
7. **优化后的简历**：完整可复制/下载文本。
8. **针对 JD 的修改建议**：改前问题、改法、对应 JD 要求或简历证据。
9. **投递前自查**：见 FR-08。

## 5. 功能需求

### FR-01 简历输入与解析

| 项目 | 要求 |
|---|---|
| 输入 | PDF、DOCX，单文件不超过 10MB；或直接粘贴文本，最多 18,000 字 |
| 校验 | 仅接受支持格式；文字内容过少的 PDF 视为扫描件/不可用；捕获文件损坏错误 |
| 处理 | 清洗零宽字符、冗余空白和连续空行；超过上限截断并提示 |
| 输出 | 展示不可编辑的原始文本预览，用户确认后才能分析 |
| 验收 | Given 扫描版 PDF，When 解析，Then 不发起模型调用并引导上传文字版文件。 |

### FR-02 目标岗位 JD 输入与关键词提取

| 项目 | 要求 |
|---|---|
| 输入 | 可选文本，最多 12,000 字 |
| 处理 | 清洗网页乱码、空白和无效换行；超长截断并告知用户 |
| 关键词 | 识别岗位名称、硬性技能、职责、业务领域、协作要求和成果指标；按 JD 中的重复、明确限定词和职责位置确定优先级 |
| 无 JD | 进入“通用优化”，不展示伪造的岗位匹配结论 |
| 验收 | Given 空 JD，When 分析，Then 输出通用优化并明确标记，不显示 JD 关键词覆盖率。 |

### FR-03 100 分制 JD 匹配评分

| 评分维度 | 权重 | 得分依据 | 扣分说明 |
|---|---:|---|---|
| 核心能力/硬性要求 | 40 | 简历中有明确技能、经历或项目证据 | JD 核心能力未出现或只有无证据关键词 |
| 相关职责与项目经历 | 30 | 已有职责与 JD 工作内容直接对应 | 相关经历较少或职责未展开 |
| 关键词自然覆盖 | 15 | JD 原词出现在相关经历、项目或技能中 | 只堆叠技能、不在案例中体现，或表述偏离 JD |
| 成果与量化表达 | 15 | 已有真实结果、指标或影响范围 | 只有职责没有结果；不得因此生成数据 |

匹配分由模型在固定评分框架内生成，并返回每个维度的得分、理由、扣分项与置信说明。职业空档、转行、频繁变动不进入 JD 匹配分，只能作为可选的简历表达提示。

**分数提示**

| 区间 | 用户提示 | 建议动作 |
|---|---|---|
| 80-100 | 匹配度较高 | 优先投递；完成投递前自查 |
| 60-79 | 有可优化空间 | 先补强核心关键词、相关案例和成果表达再投递 |
| 0-59 | 核心证据不足 | 谨慎投递；补充真实项目/能力材料或选择更匹配岗位 |

### FR-04 JD 匹配证据与缺口

系统输出 `matched_requirements[]` 与 `gaps[]`。每项匹配必须含 JD 要求和简历证据；每项缺口必须说明“为什么影响匹配”和“用户可补充的真实信息类型”。

禁止把未出现的技能、实习、项目、公司、证书、数字或时间填入用户简历。

### FR-05 优化策略与推荐结构

策略由 `config/resume_strategies.json` 承载，应用随每次分析加载当前版本。MVP 策略模块包括：

- 三句岗位定位：主要经历、核心能力与岗位关系、已有结果证明。
- 6-8 个已有关键技能按 JD 优先级重排。
- 在不破坏时间线前提下，将最相关经历及相关职责前置。
- 按“动作 + 数据 + 价值”或“数据 + 动作 + 价值”重写已有成果。
- 项目经理、产品经理和项目型经历按“项目背景 + 核心工作 + 项目成果”组织；核心工作写清目标、职责范围、关键策略、协作对象和交付物。
- 用 JD 原始关键词连接到具体案例，避免关键词堆砌。
- AI 项目采用“业务背景 + AI 方案 + 产品动作 + 数据结果”结构。
- 仅对明确出现的 Gap、转行、频繁变动提供可选说明，不推断、不计分。

### FR-06 完整优化简历与修改建议

| 输出 | 规则 |
|---|---|
| 完整优化简历 | 输出完整文本；可重排、压缩、润色原文，但不得新增事实或改写原有数据 |
| 优化内容说明 | 说明岗位定位、技能排序、经历前置、关键词嵌入和成果改写了什么及原因 |
| 项目型经历 | 统一输出项目背景、核心工作、项目成果；项目成果只采用原文已有的真实数据和业务影响 |
| 修改建议 | 按“问题—修改动作—JD/原文依据”输出；没有真实数据时提示补充真实数据 |
| 下载 | 支持 TXT 下载；PDF 排版导出为二期 |

### FR-07 可选风险说明

当且仅当用户简历明确展示连续时间空档、转行或频繁岗位变化时，提示用户可选择说明。系统不评价候选人、不将该项计入匹配分，也不自动写入最终简历。

推荐说明需简短、积极、可编辑，例如“职业调整期：完成了 [真实课程/认证/项目]，目前已具备稳定投入工作的条件”。方括号内必须由用户补充真实内容。

### FR-08 投递前自查

输出以下项目及状态：

1. 核心 JD 要求是否达到约 80% 覆盖。
2. 最强匹配证据是否在第一页或最前段出现。
3. 核心经历是否有真实成果/量化信息。
4. 关键词是否与 JD 原始表达自然对齐。
5. 是否存在需用户选择说明的明确风险点。

### FR-09 策略更新与提交

| 角色 | 操作 | 产物 |
|---|---|---|
| 策略负责人 | 修改策略 JSON 的模块、版本和日期 | 策略变更提交 |
| 运营/测试 | 通过 GitHub `Strategy Update` Issue 提交问题、规则与验收方式 | 待评审策略单 |
| 产品/算法 | 审查规则影响，运行金标回归 | 审批记录与测试结果 |
| 工程 | 合并 Pull Request、灰度发布或回滚 | 发布版本 |

策略更新不得直接在面向求职者的公开页面编辑。公开页面只显示当前策略版本，避免规则被随意篡改。

## 6. AI 设计

### 6.1 模型与上下文

模型：DeepSeek `deepseek-chat`；温度 `0`；最大输出 `3800 tokens`；单次超时 `40 秒`。模型版本、调用成本、限流值、备用模型和生产并发由工程/算法负责人待确认。

模型输入由 `resume`、`job_description`、`optimization_strategies` 和固定 System Prompt 组成。简历、JD 是不可信文本，只能作为内容源，不能改变系统规则。

### 6.2 输出 Schema

```json
{
  "match_score": 0,
  "match_summary": "string",
  "matched_requirements": ["string"],
  "gaps": ["string"],
  "headline_positioning": "string",
  "optimized_resume": "string",
  "suggestions": [{"title": "string", "detail": "string", "evidence": "string"}],
  "pre_submit_checklist": [{"item": "string", "status": "已覆盖|待补充|待确认", "advice": "string"}]
}
```

Schema 不合法、分数非 0-100 整数、超时、空结果或 API 错误均不展示不完整分析，提示用户重试或精简输入。

### 6.3 RAG 与记忆决策

一期**不采用 RAG**。简历优化策略是受控、版本化的规则，而非需要检索的大型事实库，使用策略 JSON 注入比向量检索更稳定、可测试、可回滚。简历/JD 仅用于当前请求，不做跨会话记忆和持久化。

当后续接入授权的行业术语库、岗位能力词典或已脱敏且合规的案例库，并且规模超过人工配置可维护范围时，再评估 RAG；届时必须定义知识授权、版本、生效日期、引用和回滚机制。

## 7. 数据、权限与安全

| 数据 | 用途 | 保存策略 |
|---|---|---|
| 简历文本/文件 | 当前分析 | 仅请求内存，不持久化 |
| JD 文本 | 当前匹配 | 仅请求内存，不持久化 |
| 优化策略 | 规则管理 | Git 版本控制 |

API Key 仅允许放在部署平台 Secret 或本地 `.streamlit/secrets.toml`，不得提交 Git。日志与埋点不得记录简历、JD、文件名、模型原文或密钥。

## 8. 异常与风险处理

| 场景 | 产品处理 | 需求 ID |
|---|---|---|
| 扫描 PDF/无文字文件 | 阻断解析，提示上传文字版 PDF/DOCX | FR-01 |
| 文件损坏或格式错误 | 友好错误提示，不调用模型 | FR-01 |
| 简历/JD 超长 | 清洗、截断并告知用户 | FR-01/02 |
| JD 为空 | 切换通用优化，不输出岗位匹配结论 | FR-02 |
| 模型超时、乱码、JSON 错误 | 不展示不完整结果，提示重试或精简输入 | FR-03 |
| 模型新增经历、技能或数据 | Prompt 约束；用户最终确认后使用输出 | FR-04/06 |
| JD 提示注入 | 固定系统规则，JD 仅作为内容数据 | FR-02/AI |
| 策略文件格式错误 | 停止分析并展示配置加载错误 | FR-09 |

## 9. 非功能需求与埋点

### 9.1 非功能需求

- 端到端 AI 生成最长 40 秒，生成中提供加载状态。
- 支持桌面与移动端；长文本不遮挡输入和按钮。
- 解析与输入失败必须有可执行的修复提示。
- 输出支持复制和 TXT 下载。

### 9.2 埋点（不包含正文）

`resume_parse_success/fail{reason}`、`jd_truncated`、`analysis_started`、`analysis_success/fail{reason}`、`result_downloaded`、`strategy_version_used`。

核心指标：分析完成率、结果下载率、80 分以上结果下载率、平均体验评分、内容不符合 JD 的负反馈率。阈值待 5 人内测后的产品评审确认。

## 11. 验收与上线准入

| ID | Given / When / Then |
|---|---|
| AC-01 | Given 文字版 PDF/DOCX，When 上传，Then 展示可核对的解析文本。 |
| AC-02 | Given 无效或扫描版文件，When 上传，Then 提示错误且不调用模型。 |
| AC-03 | Given 简历和 JD 已确认，When 点击分析，Then 展示固定结果 Schema 的所有关键区域。 |
| AC-04 | Given JD 核心要求在简历中无证据，When 分析，Then 在扣分/缺口中说明原因，不补写经历。 |
| AC-05 | Given 已有匹配证据，When 生成优化简历，Then 将相关经历、技能或项目调整为更符合 JD 的结构。 |
| AC-06 | Given 原文没有量化结果，When 输出建议，Then 提示补充真实数据，不生成示例数字写入优化简历。 |
| AC-07 | Given 策略版本更新，When 下一次分析，Then 页面与模型上下文均使用新版本。 |
| AC-08 | Given 用户下载结果，When 检查日志和反馈，Then 不存在简历/JD 正文或密钥。 |
